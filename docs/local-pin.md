# 本机数字PIN解锁连接

这是可选的本机便捷解锁，不把公网API凭据缩短为四位数字。后台长令牌、鉴权规则及服务端数据库均不变。

使用方式（前端部署获批后）：首次填写API地址与设备长令牌 → 填4至8位数字PIN（例如5505）→ “设置PIN保存连接”。之后重新加载/打开新页面时，连接字段不从旧sessionStorage自动恢复，输入PIN后点“PIN解锁”；解锁后继续正常同步。已有页面没有自动上锁计时器，离开前可点“锁定连接”。不改变本机计时/队列或停止正在计时的记录。

PIN通过WebCrypto PBKDF2-SHA256（210000次、独立随机盐）派生AES-256-GCM密钥，随机IV，认证加密仅保存连接地址和长令牌。PIN不发送API，不保存明文；密文在本origin的localStorage独立键time-map-connection-v1。原V1/V2计时键和导出备份格式不变，连接密文不进计时备份。设置PIN后移除旧sessionStorage连接明文；解锁只把长令牌留在当前页面使用，不重新写明文sessionStorage。

限制：四位数字仅有10000种，不抵抗本机密文被复制后的离线猜测；PBKDF2不把它变成强密码，也不能抵抗已解锁页面里的恶意脚本。请保护手机锁屏，更多位数更好。PIN不是手机用户账户、多设备配对或服务器第二因素。

错误PIN/损坏密文会拒绝解锁，不清计时数据。不记得PIN可“忘记本机连接”，然后重新填写长令牌；只删连接密文，不撤销服务端令牌或删除计时。更换设备凭据后旧密文会移除，需重新设置PIN保存新令牌，避免继续解锁旧令牌。清网站数据会同时清掉本机记录，因此不能用清缓存/卸载来重置PIN。

锁定阻止后续同步，但已发出的网络请求仍可能完成；锁定不会回滚已提交数据，也不取消服务器任务。凭据仍在sessionStorage中的旧使用方式继续兼容，未设置PIN的用户不强制迁移。页面进入后只有已配置且解锁的连接才会自动正常同步；不自动请求模型、Notion或飞书。

新增静态依赖js/connection-vault.js，Service Worker缓存名更新，部署check-static清单增至14项。静态更新时需一起复制该文件，不操作原后端构建源码或镜像记录。部署前端后PIN功能即可使用，不需修改服务器鉴权。回退到没有PIN功能的静态版本不会删除密文或计时，但旧页面需再次手动输入长令牌。

验证：Node测试覆盖加密往返、错误PIN、损坏密文、非数字PIN、连接遗忘不删计时；本地390×844 Chromium使用合成API覆盖设置/重载/错误PIN/解锁同步/锁定/遗忘，原进行中记录、版本与队列不变。原409恢复与401暂停浏览器测试也通过。iPhone实机仍需部署获批后验收；本轮没有部署或修改手机。
