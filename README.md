# 时间去向 V1 —— 从零部署和理解整套代码

> 功能：保存常用地点 → 到达开始地点计时 → 离开结束停留并开始路程 → 下次到达结束路程并开始新地点 → 每天的纵向时间轴 + 各地点汇总 + 全部路程合计 → 编辑、删除、跨天、备份恢复。

**不必安装编程软件，不必购买服务器，不必注册第三方数据库。** 只需要 GitHub 账号和 iPhone 的 Safari。全项目是纯 HTML + CSS + JavaScript + 浏览器本地存储 + Service Worker。没有联网账户，也没有定位追踪。

## 一、文件地图：每份文件干什么

```text
time-map-v1/
├── index.html              入口、按钮和文字的位置（网页的骨架）
├── styles.css              字体、颜色、排版、手机适配（网页的外衣）
├── js/
│   ├── app.js              业务总指挥：绑定按钮，操作计时，更新界面
│   ├── storage.js          数据保管员：检查、读取、原子保存本地数据
│   └── time.js             计算器：跨天裁剪、时间格式、按地点汇总
├── sw.js                   离线缓存助手：断网时也能打开上述网页文件
├── manifest.webmanifest    告诉 iPhone 这是可加入主屏幕的网页应用
├── assets/
│   ├── icon.svg            图标矢量源文件
│   ├── icon-192.png        主屏幕图标（小尺寸）
│   └── icon-512.png        主屏幕图标（大尺寸）
├── .nojekyll               告诉 GitHub Pages 不要额外处理此静态网站
├── package.json            可选：仅供开发者使用 npm test；部署不需要
├── tests/time.test.js      可选：跨天、汇总、坏备份等自动测试
└── README.md               你正在看的中文说明书
```

**怎么看代码？** 先看 `index.html`（有哪些按钮），再看 `js/app.js`（按钮做什么），然后看 `js/storage.js`（为什么关页面数据不丢），最后看 `js/time.js`（每天时长怎么汇总）。`styles.css` 只负责美观。

每份**可加注释的源码**都在开头写了说明。`manifest.webmanifest` 和 `package.json` 必须使用标准 JSON 格式，不允许写 `//` 注释；图标 PNG 是图片也不能写代码注释，因此它们的用途在上表说明。

## 二、整套代码是怎样跑起来的？

### 1. 第一次打开

```text
iPhone Safari 访问 GitHub Pages 网址
    ↓
index.html 出现 → 加载 styles.css（画好外观）
    ↓
加载 js/app.js（主程序入口）
    ├── import js/storage.js（准备读写数据）
    └── import js/time.js（准备计算时间）
    ↓
app.js 的 start() 执行 → storage.loadState()
    ↓
从 localStorage（当前手机的网页本地存储）读回历史记录
    ↓
renderAll() 把「当前计时、地点按钮、报告、时间轴」显示出来
    ↓
注册 sw.js → 缓存程序文件 → 以后可离线打开
```

`import` 就是“这个文件需要使用另一个文件里写好的工具函数”。`renderAll()` 就是“用最新数据刷新屏幕”。

### 2. 日常按钮的四种情况

```text
【起床 / 第一次记录】
点击「家 · 到达」→ app.arrive() → 新建“家”记录 start=当前时间
                                    → storage.saveState() → 刷新界面

【离开家】
点击「离开」→ app.leave() → 给“家”记录加 end=当前时间
                              → 新建“路程”记录 start=当前时间
                              → 保存 → 刷新

【到达图书馆】
点击「图书馆 · 到达」→ app.arrive() → 给“路程”加 end=当前时间
                                      → 新建“图书馆”记录 start=当前时间
                                      → 保存 → 刷新

【还在图书馆】
关闭网页 → 只是界面消失；已经保存的 start 不会消失
隔两小时重新打开 → 读回原 start → 用“现在 - start”算出 2 小时
```

**重点：** 手机不是依靠网页持续运行一秒一秒“累加计数”，而是只保存**开始和结束的真实时间戳**。时间戳就是一个确切的时刻（内部用从 1970 年起的毫秒数表达）。因此锁屏、退出、断网，都不妨碍下次根据时刻算出经过时长。

如果已经处于一个地点，却点击另一个地点：会提示“请先离开”。处于路程状态时：点击目的地就会自动完成路程并开始地点计时。没有任何活动记录时：点击地点便直接开始计时。所有操作均只有**一个当前活动段**。

### 3. 每日统计、跨天与历史

```text
点击查看某一天 → app.renderDay()
  ├── time.segmentsOfDay(历史记录, 选定日期)
  │   把每条记录截取出“落在当天 00:00–次日 00:00 的部分”
  │   例如 家：21 日 23:00–22 日 01:00
  │   → 21 日计 1 小时；22 日也计 1 小时
  ├── time.dayTotals()
  │   同一地点的多段时长加起来；所有路程相加
  └── app.renderDay() 把数字、横条和纵向时间轴画到屏幕上
```

`storage.js` 不负责计算，`time.js` 不负责存储，`app.js` 负责把它们连接起来，降低以后修改时影响其他模块的概率。

### 4. 修改和删除时间记录

点击时间轴旁的「修改」→ 修改地点类型、地点名称、开始/结束时间 → 先检查记录是否会重叠 → 合法才保存。若两段原来刚好在同一时间点首尾相接，修改交界时会**同步调整相邻一段**：例如原来「在家 10:00–12:00 → 路程 12:00–12:30」，将离家时间改为 11:50，会自动使路程起点变为 11:50。

点击「删除」→ 确认 → 移除对应段 → 留下未统计的空白。删除正在进行的段，会变为“未开始”状态。**V1 没有手动补建任意漏记记录的功能**；可以修改已有记录时间。如果发现重大漏记，建议在删除前先备份。

### 5. 备份与恢复

导出 → `app.js` 把整个数据对象转成 JSON 文本 → 手机下载到「文件」或 iCloud Drive。导入 → 读取 JSON → `storage.validateState()` 检查结构、时间和顺序 → 显示覆盖确认 → 一次性写回本机。**不能跨设备实时同步**：另一台 iPhone 必须手动导入备份。

## 三、最简单的部署（网页直接上传 GitHub）

1. 在电脑上下载并解压本项目 ZIP，得到 `time-map-v1` 文件夹。
2. 打开 [https://github.com](https://github.com)，登录后点击右上角 **+ → New repository**。仓库名输入 `time-map-v1`，选 **Public**，点击 **Create repository**。网站程序本身会公开，但你的地点、时间记录不会被上传（它们储存在手机）。**不要把个人 JSON 备份上传到 GitHub。**
3. 在仓库首页选择 **uploading an existing file**（或 **Add file → Upload files**），把解压后的 `time-map-v1` 文件夹里**的所有文件和子文件夹**拖到上传区域。**注意：仓库根目录要直接看到 `index.html`，而不是多套一层 `time-map-v1/`。** 如果浏览器不支持拖整个文件夹，可以用 GitHub 网页编辑器建立路径，或使用 GitHub Desktop 上传文件夹；确保 `js/`、`assets/` 子目录结构被保留。
4. 点击页面底部 **Commit changes**。进入仓库 **Settings → Pages**；**Build and deployment → Source → Deploy from a branch**；**Branch → main → /(root) → Save**。
5. 等 Pages 页面出现站点地址。一般形如 `https://你的GitHub用户名.github.io/time-map-v1/`。在电脑先打开，添加“家”“图书馆”，验证到达、离开、时间轴。再打开手机 Safari 同一网址。
6. 在 iPhone 的 **Safari → 分享按钮 → 添加到主屏幕（Add to Home Screen）**；若界面有 **作为网页 App 打开（Open as Web App）**，打开它；点击 **添加**。此后从主屏幕图标一键进入。
7. 第一次**联网**打开一次并等待网页正常显示；确认后切换飞行模式尝试从同一主屏幕图标打开，以验证离线缓存是否准备妥当。

如果网页显示 404，先核对 `index.html` 是否在仓库根目录、Settings → Pages 是否选了 `main` 和 `/(root)`、以及地址末尾是否包含仓库名。**用 `file://` 双击打开 HTML 文件并不是可靠的测试方式**，因为浏览器通常禁止本地文件使用 JS 模块与 Service Worker；请走 GitHub Pages 或下面的本地服务器方式。

### 电脑本地预览（可选）

如果你的电脑安装了 Python，在包含 `index.html` 的目录里打开终端：

```sh
python -m http.server 8000
```

浏览器打开 `http://localhost:8000`。这样加载 ES modules 和离线服务都更接近真实部署。

### 自动测试（可选）

若电脑有 Node.js，项目目录里执行：

```sh
npm test
```

测试跨午夜、地点合并、路程总和、时间重叠校验等。这一步不是部署前提。

## 四、特别重要的使用边界

- **数据保存在设备本地，不是 GitHub：** GitHub 只存放公开的源代码和图标。关闭或锁屏后计时起点仍被保存；但清除 Safari/网页 App 网站数据、卸载应用、系统清理或更换手机，可能会丢失本地记录。建议**每周导出备份**。如果在 Safari 和主屏幕 App 之间切换，iOS 可能将两者视为不同的独立存储空间；日常使用请固定从**同一个主屏幕图标**进入。
- **离线条件：** 需要先联网成功访问过一次，让 Service Worker 缓存程序；断网后可继续操作和记录。不是锁屏实时后台定位，它不使用 GPS、不提醒自动到达，也不保证浏览器长期永不清理缓存。
- **真正的「一键入口」是主屏幕图标：** 点击图标打开应用，再点里面的「离开」或地点「到达」。**V1 不是锁屏小组件，也不能在未打开网页的情况下直接执行到达/离开按钮。**
- **时间精度：** 存储为毫秒时间戳，界面显示到秒；报告以本机当前时区的自然日分割。若跨时区旅行，历史日归属会按当时查看的设备时区重新计算。若手动调错设备时间，也会影响准确性。
- **跨天：** 晚上 23:00 在家、第二天 08:00 离开，系统将自然分开计入两天，不需要凌晨按任何按钮。持续的路程也会跨天累计，**所以到达目的地时记得点击到达**。
- **名称和记录：** 地点改名会影响其所有历史显示；删除常用地点不删除历史片段。删除一段以后，空白区间不计入统计。统计里的“已记录”不强制等于 24 小时。
- **修改程序版本：** 替换代码上传 GitHub Pages 即可；如修改了 `sw.js` 的缓存文件列表，建议增加 `CACHE_NAME` 的版本号。**不要自行修改 `STORAGE_KEY` 或数据格式版本号**，否则旧数据可能无法读取；修改前先导出 JSON 备份。

## 五、最短验收步骤

1. 添加「家」「图书馆」。到达「家」→ 看见当前在家计时。
2. 离开 → 当前应变成「路程中」。
3. 到达「图书馆」→ 路程停止，图书馆开始计时。
4. 查看今天 → 时间轴出现「家 → 路程 → 图书馆」，汇总有两个地点及合并路程。
5. 关闭网页，再打开 → 应继续显示图书馆已持续的时间。
6. 修改某条已完成段的结束时间 → 查看下一段开始时间是否同步变化。
7. 导出 JSON，确认手机「文件」里能找到；再用导入验证恢复。切飞行模式复核主屏幕能否启动。

> 非功能：V1 不提供 GPS 自动判断、不提供多设备自动云同步、不提供原生 iOS 锁屏小组件、不提供“从主屏幕图标直接执行按钮”的快捷指令、不提供手动创建任意过去记录。这些留待未来按需扩展。
